REFERENCE

Citing a Result

A citation identifies the software. It does not identify a run. A methods section needs both.

Citing the Software

CITATION.cff at the repository root carries the metadata in Citation File Format. GitHub renders it as a "Cite this repository" button and reference managers read it directly.

There is no DOI yet. It is deliberately absent rather than invented: a Zenodo deposit mints one per release and one for the project as a whole, and that deposit is the next step. Until then, cite the version and the commit.

BIBTEX 
@software{pretium,
  author  = {Coombes, Simon},
  title   = {pretium: a deterministic market simulator with a real
             limit order book},
  version = {0.3.0},
  url     = {https://github.com/simoncoombes/pretium},
  note    = {Commit <sha>. No DOI assigned; see CITATION.cff}
}

Citing a Run

Seven things identify a market and what happened in it. Miss any one and the result cannot be rebuilt.

WhatWhy it is needed
package versionTrajectories change across versions. A figure from an earlier known-answer baseline is wrong by construction, not approximately right.
seedThe market. On its own it identifies nothing, because the same seed over a different roster is a different market.
universe fingerprintWhich roster, in which order. Tickers do not distinguish rosters, because they are generated positionally: random(40, seed=1) and random(40, seed=99) share every name and no fundamentals.
how the universe was builtThe fingerprint proves two rosters match; it does not let a reader construct yours. Give the constructor call, or ship the EDGAR snapshot.
macro initial conditionsDay zero, plus any scenario path or pin.
model fingerprintA preset name, or custom-XXXXXXXX. A custom model cannot present as a shipped one.
strategy fingerprintPresent when the strategy was a StrategySpec. Empty for a hand-written agent, which honestly says: cite code at a commit instead.

Or Ship One File

RunManifest gathers all of it, fingerprints each part, and carries the expected result digest, so a reader is told whether they rebuilt the same market rather than eyeballing numbers.

PYTHON 
import pretium as pt

universe = pt.Universe.random(40, seed=111)
spec = pt.StrategySpec.momentum(lookback_days=1.0, top_k=5)
engine = pt.Engine(seed=42, universe=universe)
engine.run_days(252)

manifest = pt.RunManifest.of(engine, seed=42, universe=universe,
                             strategy=spec)
open("run.json", "w").write(manifest.to_json())

# the reader, with the package and this file and nothing else:
same = pt.RunManifest.from_json(open("run.json").read()).reproduce()

reproduce() checks the build's arithmetic behaviourally before replaying, and refuses on any mismatch, naming what differs. A manifest that silently reproduced a different market would manufacture false confidence, which is worse than no manifest.

For a custom model the manifest embeds the full coefficient dictionary, so a modified market rebuilds bit for bit or is refused by name.

Citing a Realism Claim

Do not quote the numbers on Realism and Limits for your own roster. Cite envelope.json, which carries the per-statistic detail, the gap list and the provenance, and re-measure the panel on your own universe with facts.measure if your roster is not sector-balanced. The determinism baseline for the current era is known-answer v11, digest 60d47572…0de590, which the release workflow checks inside every wheel before it uploads; every era boundary carries a different one, so a digest is an era marker rather than a version number. For the check that matters to a citation, compare pretium.model_preset()["name"] against the preset named in envelope.json: if they differ, the published page describes a different model than the one you are running.

A Worked Methods Paragraph

Strategies were evaluated on pretium 0.3.0 (commit <sha>), model preset pt-v12, over a 40-instrument universe built with Universe.random(40, seed=111) (fingerprint 5d8de78b55aad752), simulation seeds 1 to 30, 252 trading days, default day-zero macro state and no scenario. The momentum strategy is StrategySpec.momentum(lookback_days=1.0, top_k=5), fingerprint <sha256>. Run manifests and order logs are archived at <location>. Realism of the shipped preset at this horizon is as published in envelope.json, which names the preset the figures describe; absolute returns are not claimed to forecast live results.

The last clause is not boilerplate. It is the one claim this simulator cannot support at any horizon or preset.
