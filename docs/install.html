GETTING STARTED

Install and Versioning

Wheels, extras, what moves between versions, and how to check bit-identity on your own machine.

Install

SHELL 
pip install pretium              # core, no dependencies
pip install "pretium[rl]"        # + numpy, gymnasium
pip install "pretium[arrow]"     # + pyarrow
pip install "pretium[claude]"    # + the Claude agent example's deps
pip install "pretium[mcp]"       # + the MCP server
Requirement
Python3.11 or later.
Wheelsabi3, so one wheel per platform covers every supported Python.
Rust toolchainNot needed. The extension ships compiled.
DependenciesNone for the core package. Arrow output works through the buffer protocol, so polars, pandas, pyarrow and duckdb read it without pretium depending on any of them.

Using it from Rust

The engine is a Rust crate and is published on crates.io as pretium, the same code the Python wheels are built from.

cargo add pretium

Docs at docs.rs/pretium. The crate carries the engine, the presets and the determinism guarantees; the Python package adds the harness, the evaluation layer and the notebooks.

Build Targets

The release builds and compares five Python wheel targets. Anything else needs a source build and is outside the determinism claim.

PlatformArchitecture
Linuxx86_64, aarch64
macOSarm64, x86_64
Windowsx86_64

There is a sixth target that is not a wheel. The crate also compiles to wasm32-unknown-unknown for the browser, and that build produces a digest identical to the native one, and at 0.3.0 it is 204,290 bytes raw and 72,981 gzipped. Build it with tools/wasm/build.sh, which builds, runs wasm-bindgen and verifies the digest in one command. Running in the Browser has the measurement and the two places it is still loose.

If the Import Fails

SymptomCause
pip builds from source, or reports no matching distributionYour platform is not one of the five, or your Python is older than 3.11. Check pip debug --verbosity 1 against the tag list above.
ImportError on pretium._coreThe compiled extension did not install. Reinstall with --force-reinstall --no-cache-dir.
ModuleNotFoundError: gymnasium or pyarrowYou called an extra's surface without installing the extra.
Numbers differ from a published figureCheck the preset and the version before anything else: pt.__version__ and pt.model_preset()["name"]. Trajectories change across known-answer baselines.
A browser build disagrees with a native oneCheck that relaxed SIMD is off, since it is non-deterministic by design. If a digest refuses to hash, a non-finite value appeared, which is a real failure rather than a mismatch to work around.

What Moves Between Versions

Pre-1.0, the API may change. What has a stated policy is the simulated output, and it has five independent version numbers:

Versioned thingPolicy
package versionOrdinary semver-ish. Pre-1.0 the Python surface can move.
model presetNever changes once shipped. A recalibration arrives as a new name, and every earlier name keeps reproducing exactly what it always did.
known-answer baselineMoves when a change legitimately alters simulated output. When it moves, every seeded trajectory changed. Results from either side are not comparable at the same seed.
SPEC_VERSIONStrategy-spec grammar. Adding a kind keeps old specs valid; changing what a kind means would be a new version.
RNG derivationA contract, pinned by a golden test. Changing it is an era boundary in its own right.

The practical rule, then, is to pin the package version in anything you publish and to re-measure rather than inherit a number across a baseline change. facts.measure takes the same arguments the rest of the library does for exactly that reason.

Checking Bit-Identity Yourself

The published record is measured on all five wheel targets at commit ad91026, and the current baseline is confirmed on macOS arm64 only. To check your own target, run the known-answer test and compare its digest against the committed baseline:

SHELL 
# from a clone, against the committed baseline for this build
pytest tests/test_known_answer.py -q

# the Rust side: no platform-varying transcendental reaches the source
cargo test --manifest-path rust/Cargo.toml mathx_parity

# the browser build, digest verified as part of the build
tools/wasm/build.sh

A pass means your machine reproduces the committed digest bit for bit, and a failure names the first value that diverged. If you are on a platform outside the five, that result is worth reporting, since cross-platform identity is the claim most in need of independent measurement.

Checkpoints and Forking

A run can be frozen and resumed, or forked into futures from an identical state, which is how you ask what a single decision was actually worth. Checkpoints and Forking is the guide; the shape of it is:

PYTHON 
cp = pt.Checkpoint.of(engine, universe=u, seed=42)   # survives the process
left, right = pt.branch(engine, 2, universe=u, seed=42)

left.pin_macro(corporate_bond_yield=0.09)
left.run_days(30)
right.run_days(30)                      # same noise, different macro

A checkpoint carries twenty-one RNG numbers: state, increment and Box-Muller spare for each of the seven streams, which are market, economy, external, jumps, volume, news and per-name volume. It carried nine when there were three streams and grew by three each time a mechanism got its own, so restore reads the era off the length: nine, twelve, fifteen and eighteen all still restore, keeping this engine's seed-derived position for the streams the snapshot predates, which is what lets a checkpoint written before a mechanism existed replay as it did then. Only a pre-split snapshot with three numbers is refused, with its era named, because it froze a single-stream market this version cannot continue bit-exactly.

Common questions

How do I install pretium?

pip install pretium. The core package has no dependencies at all. The extras are opt-in: [rl] adds numpy and gymnasium, [arrow] adds pyarrow, [mcp] adds the MCP server, and [claude] adds what the Claude agent example needs.

Does it need numpy or pandas?

No. The core package depends on nothing. Runs come back as Arrow tables that read zero copy into polars, pandas, pyarrow or duckdb, and the package requires none of them: you use whichever you already have.

How do I check I am getting bit-identical results?

The repository ships a known-answer baseline: a fixed seed and roster with a recorded SHA-256 of the resulting simulation. Re-running it on your machine and comparing the digest is the check, and it is what the determinism workflow runs on every supported platform.

Will upgrading change my results?

Only at an era boundary, and the release notes say when one happens. Pin the preset by name and your numbers survive the upgrade; the current default is pt-v12.
