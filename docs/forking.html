GUIDE

Checkpoints and Forking

Freeze a market and resume it later, or split it into several futures from one identical state. This is the machinery for asking what a single decision was worth.

Why You Would Do This

You want to know what one choice cost you, and there is no way to isolate that in a single run. Run a strategy through a crisis and you learn what happened; fork the market the day before the crisis and you learn what would have happened if you had de-risked, on exactly the same tape, with exactly the same noise. The branches share no memory, so nothing you do to one leaks into the other, which is what makes it a controlled experiment rather than two runs that happened to start alike.

It is also how you avoid paying for the same hundred days twice. Reaching day 60 costs whatever it costs; forking from there is close to free.

Two Tools, and They Are Not Interchangeable

pt.branch(engine, count, universe=, seed=)Forks a running engine in constant time by copying its state, columns and generator position included. Measured at under a millisecond for a sixty-day forty-instrument market, against 2,740 ms to reach the same point by replaying its log. Lives in memory, dies with the process.
pt.CheckpointSerialises the inputs and the order log, so the state survives the process and can be published. Resuming replays the log, so it costs roughly what reaching the state cost the first time.

So: branch when the experiment happens now, Checkpoint when someone else needs to start where you started.

Forking a Live Engine

PYTHON 
import pretium as pt

universe = pt.Universe.random(40, seed=7)
engine = pt.Engine(seed=42, universe=universe)
engine.run_days(60)                     # the shared history

# both branches carry the full state, including the RNG position
calm, shocked = pt.branch(engine, 2, universe=universe, seed=42)

shocked.pin_macro(corporate_bond_yield=0.09)   # one thing differs
calm.run_days(30)
shocked.run_days(30)

calm_close = calm.bars(grain="day")
shocked_close = shocked.bars(grain="day")

universe and seed are required because an engine carries neither: it is built from them and keeps them nowhere. The seed barely matters here, since the generator position is restored over whatever it produced, but the universe does: the columns are positional, so a mismatched roster would attach every value to the wrong instrument. The engine refuses that rather than doing it quietly.

A fork of a custom-model run prices under its parent's coefficients, read off the live engine, so a branch cannot silently revert to the shipped preset.

Checkpoints That Outlive the Process

PYTHON 
cp = pt.Checkpoint.of(engine, universe=universe, seed=42,
                      label="pre-shock, day 60")

open("day60.json", "w").write(cp.to_json())

# later, or elsewhere, or in someone else's hands:
cp = pt.Checkpoint.from_json(open("day60.json").read())
engine = cp.resume()

# or several futures at once
futures = cp.branch(3)

Checkpoint.of takes the universe and the seed for the same reason branch does, and it records them so the checkpoint carries the inputs it will need rather than discovering at resume time that it cannot reproduce anything.

resume(universe=...) lets you restore onto a roster you already hold. It is checked against the recorded fingerprint and refused on a mismatch, because tickers are generated positionally: two universes can share every name and no fundamentals, so comparing names would be checking almost nothing. The error message says what a mismatch would give you, which is right prices and wrong fair values.

Full Example: What Did De-risking Cost?

Sixty days of shared history, then the same market twice: once holding the book through a rate shock, once cutting exposure the day before it starts. Same seed, same noise, one decision different.

PYTHON 
import pretium as pt

universe = pt.Universe.random(40, seed=7)
spec = pt.StrategySpec.momentum(lookback_days=1.0, top_k=5)

# 1. shared history
engine = pt.Engine(seed=42, universe=universe)
engine.run_days(60)
print(engine.draws_by_stream())          # the position both branches inherit

# 2. publish the fork point, so the experiment is checkable
cp = pt.Checkpoint.of(engine, universe=universe, seed=42,
                      label="day 60, pre-shock")
open("day60.json", "w").write(cp.to_json())

# 3. two futures from one state
held, derisked = pt.branch(engine, 2, universe=universe, seed=42)

# 4. the same shock reaches both; only the exposure differs
shock = pt.Scenario.rate_shock(start=0.025, end=0.05, over=15)
for eng, gross in ((held, 1.0), (derisked, 0.4)):
    for day in range(30):
        shock.apply(eng, day)
        eng.run_days(1)

# 5. and the counterfactual is exact, because the noise was identical
print(held.draws_by_stream()["market"] == derisked.draws_by_stream()["market"])
OUTPUTILLUSTRATIVE
# 1.
{'market': 9360000, 'economy': 1440, 'external': 0}

# 5.
True

The last line is the point. Equal market-stream draw counts mean the two branches consumed, and therefore saw, an identical noise sequence, so the difference between their P&Ls is the decision and nothing else. That is a number no backtest can produce, because history only ran once and it ran with your orders in it.

What Travels, and What Does Not

RNG positionNine numbers: state, increment and Box-Muller spare for each of the three streams. A pre-split snapshot carrying three is refused on restore with its era named, because it froze a single-stream market this version cannot continue bit-exactly.
modelThe parent's coefficients. A custom-model checkpoint resumes under the custom model or refuses.
universe · seed · macro · order logEverything a resume needs, which is why they are arguments rather than assumptions.
schemaA checkpoint written by a newer version is refused rather than read partially.
