GUIDE

The Agent Harness

Any object with an act method is an agent. This page is the whole contract with the harness: what it hands you, what you return, and how it scores you.

The Contract

An agent needs one method: act(obs) receives an Observation and returns a dict of share quantities keyed by ticker, where positive buys, negative sells, and a ticker you omit or set to zero does nothing. There is no base class to inherit and nothing to register, so any object with that method will do.

PYTHON 
class MyAgent:
    def act(self, obs):
        if not obs.is_first_step_of_day:      # once a day, correctly
            return {}
        ticker = obs.tickers[0]
        shares = 0.01 * obs.avg_volume(ticker)   # size by participation
        return {ticker: shares}

scores = pt.evaluate({"mine": MyAgent()}, seed=7,
                     universe=universe, days=10)
print(scores["mine"].return_pct, scores["mine"].trades)
THE TRAP THAT HAS COST PEOPLE REAL RUNS

obs.step counts the whole run, not the day. At the default six steps a day, day 1 starts at step 6 and day 3 at step 18. So if obs.step != 0: return {} reads like a once-a-day guard and is a once-a-run guard: the agent trades on the first step of day zero, never again, and produces a scorecard with trades=1 and no errors. It looks exactly like an agent that considered the market and declined.

Use obs.is_first_step_of_day, obs.is_last_step_of_day or obs.step_of_day. The library cannot catch the mistake, because it is arithmetic on an integer with no call to intercept.

What You Are Handed

Observation is deliberately narrow: everything on it is something a real trader could see, and nothing on it is something only the simulator knows.

MemberWhat it is
obs.stepIndex over every decision point in the run. Day 1 starts at 6 under the default cadence.
obs.step_of_dayIndex within the day, 0 at every open. Derived, so it cannot disagree with step.
obs.is_first_step_of_dayTrue at the day's opening decision point. The correct once-a-day guard.
obs.is_last_step_of_dayTrue at the day's final decision point, before the close.
obs.dayDay index in the run.
obs.steps_per_dayThe harness cadence. Exposed because an agent reasoning about a horizon cannot infer it at step zero.
obs.tickersThe roster, in index order.
obs.pricesCurrent prices, aligned to tickers.
obs.price(ticker)One price by name.
obs.book(ticker)The live order book, with the depth a trader would see.
obs.avg_volume(ticker)Average daily volume. Public information, and how size should be reasoned about.
obs.participation(ticker, shares)That order as a fraction of average daily volume.
obs.position(ticker)Your current holding, in shares. Zero if none.
obs.portfolioThe Portfolio: cash and positions.
obs.engineThe engine itself. Available, and using it for anything a trader could not see makes your result a different claim.
SIZE IN PARTICIPATION, NOT SHARES

Impact scales with participation. The same 13.7 million shares is 0.05x a day's volume in one name here and 407x in another; the first order moves nothing and the second moves the price 47%. An agent sizing in flat share counts is not choosing a position, it is running a different experiment per instrument.

The Two Objects You Reach Through

obs.portfolio is a Portfolio: your cash and your holdings.

portfolio.cashUninvested cash.
portfolio.positionsA dict of ticker to Position. A ticker you hold nothing in is absent rather than present at zero, which is why obs.position(ticker) exists.
position.quantityShares held. Negative when short.

obs.book(ticker) returns the live OrderBook, with the depth on each side as PriceLevel entries carrying a price and a size. That is what lets an agent size against real liquidity instead of guessing: walk the levels and you know what your order will actually pay before you send it.

The Optional Second Method

explain(day) is optional, and returns the factor you believe drove the largest recent move, as one of the nine names in The Nine Components. The harness compares your answer against the engine's own attribution and reports the hit rate as explanation_accuracy on the scorecard.

The signature is explain(self, day), not explain(self). Get it wrong and nothing raises where you will see it: the harness records the error per day and reports explanation_accuracy as None, so the column reads - and looks like the feature is switched off.

PYTHON 
class MyAgent:
    def act(self, obs):
        ...

    def explain(self, day):
        return "momentum"        # one of the nine factor names

How the Harness Runs You

pt.evaluate owns the session, and its defaults are the shape of your run, so they matter more than most defaults do.

ArgumentDefaultWhat it does
agents-A dict of name to agent instance or StrategySpec.
seed-The market. Required.
universe-The roster. Required.
days5Trading days to run.
steps_per_day6Decision points per day. The clock advances between them, so a stepped day is bit-identical to one unbroken session.
ticks_per_step65Minutes per step. Six times 65 is the 390-minute day.
cash1_000_000.0Starting cash.
max_leverage2.0Gross exposure cap. Orders that would breach it are rejected and counted in rejected.
macroNoneDay-zero macro state.
scenarioNoneA macro path to impose.
modelNonePreset name or ModelParams. Every agent in one call runs the same model, because scoring across models would compare markets.
start(9, 30, 3)Session start time.

Agents are stateful, and one instance cannot be reused across two calls. Build a fresh instance per evaluation, or pass a factory, as pt.rank does.

No fees or commissions are charged. Everything an order costs you comes from the book: the spread you cross and the levels you consume. Borrow costs are not modelled either, so a short is free to hold.

What You Get Back

You get one Scorecard per agent, and as_dict() returns every field on it. Note that there is no Sharpe or drawdown here: compute those from bars if you want them.

FieldMeaning
nameThe key you passed in.
pnlProfit and loss in currency.
return_pctReturn as a percentage.
final_net_worthCash plus marked positions at the end.
tradesFills executed.
turnoverTraded notional.
impact_bpsYour footprint against the same seed with nobody trading. Read it over a day or two, not weeks: fills feed back into the price process, so the gap compounds and by day three the sign belongs to the seed.
max_leveragePeak gross exposure reached.
rejectedOrders refused, usually by the leverage cap.
errorsExceptions your agent raised, per step. Check this before reading anything else.
explanationsYour explain answers beside the engine's.
explanation_accuracyShare of days you named the right factor, or None if you did not implement explain.
seed · universe_fingerprintWhich market this came from. A leaderboard without both is a table that cannot be rerun.
strategy_fingerprintSet when the agent came from a StrategySpec. Empty for a hand-written agent, which is the honest reading: that result is reproducible only by citing code at a commit.
model_fingerprintWhich coefficients priced it.

A Complete Custom Agent

A complete agent that buys the cheapest names against fair value, sizes by participation, rebalances once a day and explains itself, which you can paste and run as it stands.

PYTHON 
import pretium as pt

class ValueAgent:
    """Buy the most undervalued names, one decision a day."""

    def __init__(self, top_k=5, participation=0.02):
        self.top_k = top_k
        self.participation = participation

    def act(self, obs):
        if not obs.is_first_step_of_day:
            return {}

        # rank by discount to fair value, which a real trader would
        # estimate; here we use our own crude proxy: price vs its own
        # 5-day mean, held on the agent.
        history = getattr(self, "_hist", [])
        history.append(list(obs.prices))
        self._hist = history[-6:]
        if len(self._hist) < 6:
            return {}

        scores = []
        for i, ticker in enumerate(obs.tickers):
            mean = sum(h[i] for h in self._hist) / len(self._hist)
            scores.append(((obs.prices[i] - mean) / mean, ticker))
        scores.sort()
        picks = [t for _, t in scores[: self.top_k]]

        orders = {}
        for ticker in picks:
            target = self.participation * obs.avg_volume(ticker)
            delta = target - obs.position(ticker)
            if abs(delta) > 1:
                orders[ticker] = delta
        return orders

    def explain(self, day):
        return "reversion"

universe = pt.Universe.random(30, seed=11)
scores = pt.evaluate({"value": ValueAgent(),
                      **{k: v for k, v in pt.reference_agents(seed=3).items()}},
                     seed=7, universe=universe, days=20)

for name, card in scores.items():
    print(f"{name:16s} {card.return_pct:+7.2f}%  trades={card.trades:4d} "
          f"errors={len(card.errors)} why={card.explanation_accuracy}")

Measured: pretium 0.3.0, pt-v12, the code above it run verbatim. Nothing is edited, which is the point of the block.

Read errors first, and both failure shapes are in front of you. The QUIET one is a guard bug: a suspiciously low trades count with an EMPTY error list, which is the trap at the top of this page. The LOUD one is the value row here, 5 trades against 56 errors, every one of them trade would take leverage to N above the 2.00x limit. Sizing at 2% of average volume across five names asks for far more than a $1,000,000 account can carry, so the harness rejects the order instead of filling it. That agent is not a bad strategy, it is an unsized one, and its why=0.0 is the same story: it answers "reversion" every day whatever moved. Then remember the oracle reads the true mispricing, so it is a reference rather than a competitor, and one seed ranks the seed as much as the agents. Take it to many markets before you believe an ordering.
