GUIDE

Testing Your Edge

A backtest runs one market, so it cannot tell you what your result rests on. Atlas runs hundreds of slightly different markets and shows you which model settings moved your number, what shape the effect had, and what trade-offs exist.

When You Need This

You tested a strategy and it looks good. Before you rely on it, ask whether the edge would still be there if the market were a bit different. Atlas answers that by running your measurement across hundreds of variations and showing which settings your result tracks.

Atlas does not optimise anything. survey measures, the analysis methods describe, and there is no target, no gradient and no best vector. Most users never need it. You need it for this second-order question, and for calibration work.

Example: Testing a Momentum Edge

A researcher has a momentum agent that does well on the shipped preset, and wants to know whether the edge lives in one corner of the model. The session below moves three parameters, measures the agent at 500 points, and asks the table what the Sharpe depends on.

PYTHON 
from pretium import atlas
import pretium as pt

universe = pt.Universe.random(40, seed=111)

axes = atlas.axes_for(
    ["market_factor_sigma", "garch_alpha", "momentum_theta"],
    ranges={"momentum_theta": (0.0, 0.4)},   # override any default box
)

def measure(vector):
    model = pt.ModelParams.from_preset("pt-v3", **vector)
    scores = pt.evaluate({"mine": MyAgent()}, seed=7,
                         universe=universe, model=model)
    return {"return_pct": scores["mine"].return_pct,
            "impact_bps": scores["mine"].impact_bps}

s = atlas.survey(axes, measure, samples=500)
s.save("survey.json")     # measure once, ask many questions later

Then interrogate the table:

PYTHON 
s.sensitivity("return_pct")   # which parameters move it, ranked
s.profile("momentum_theta", "return_pct")   # what shape the effect has
s.pareto({"return_pct": "max", "impact_bps": "min"})
print(s.explain("return_pct"))

How to read the answers. If momentum_theta dominates the sensitivity ranking, the edge rides the mispricing herding term, the same term that made pt-v1 read +0.249 at lag one and that pt-v3 turns down to a measured +0.0375. That edge is an artifact of the model and will not transfer. If the return is flat across all three ranges then the edge is at least robust to the market being somewhat different, which is the most a simulator can say for it.

MyAgent here is any object with an act method (see The Agent Harness), and measure_with_seed(vector, seed) is the same measurement taking an explicit seed. You write the measure function yourself, so Atlas works for any question: realism statistics, a Sharpe, a fill rate, an agent's score. They are all the same shape.

Confirming on Fresh Seeds

A survey runs at screening resolution: few seeds per point, so the map stays affordable. Good enough to rank candidates, not good enough to believe one. Anything the map surfaces gets re-measured on disjoint seed blocks before it is believed:

PYTHON 
s.confirm(candidate, baseline, measure_with_seed,
          seed_blocks=[range(201, 231), range(301, 331)])

confirm refuses to run on seeds that overlap the survey's. The full story of why, with the reversal that motivated it, is in the Atlas reference, along with every method, the failure modes, and what a survey cannot tell you.

Tracing an Edge to One Dial

The clearest edge-that-does-not-transfer in this library, measured end to end. Momentum agents profit here partly because returns trend, and the trendiness is one dial: momentum_theta, the herding coefficient. Survey it and watch your edge track it.

PYTHON 
import pretium as pt
from pretium import atlas

universe = pt.Universe.random(40, seed=111)
spec = pt.StrategySpec.momentum(lookback_days=1.0, top_k=5)

# 1. pick the axes. momentum_theta is the herding knob; the other two
#    are volatility, included so the answer is not one-dimensional.
axes = atlas.axes_for(
    ["momentum_theta", "garch_alpha", "market_factor_sigma"],
    ranges={"momentum_theta": (0.0, 0.4)},
)

# 2. check the plan before spending anything on it
for v in atlas.plan(axes, samples=256)[:3]:
    print(v)

# 3. measure your own outcome AND the statistic you suspect drives it
def measure(vector):
    model = pt.ModelParams.from_preset("pt-v3", **vector)
    panel = pt.facts.measure(seed=7, universe=universe, model=model)
    scores = pt.evaluate({"mom": spec}, seed=7, universe=universe,
                         days=126, model=model)
    return {"return_pct": scores["mom"].return_pct,
            "impact_bps": scores["mom"].impact_bps,
            "return_acf1": panel["return_acf1"]}

s = atlas.survey(axes, measure, samples=256)
s.meta["seeds"] = [7]            # required before confirm() will run
s.save("edge-survey.json")

# 4. what moves the return?
print(s.sensitivity("return_pct")["correlations"])

# 5. what shape is the effect?
for b in s.profile("momentum_theta", "return_pct", bins=6)["bins"]:
    print(round(b["low"], 3), b["n"], b["median"])

# 6. re-measure the finding on seeds the survey never saw
hi = {"momentum_theta": 0.30, "garch_alpha": 0.09,
      "market_factor_sigma": 0.016}
lo = {**hi, "momentum_theta": 0.03}
print(s.confirm(hi, lo, measure_with_seed,
                seed_blocks=[range(201, 231), range(301, 331)]))

Read step 4 and step 5 together. momentum_theta dominates at rho 0.74 while the two volatility axes read near zero, and the profile climbs steadily across the range with no flattening. Step 6 confirms it on sixty fresh seeds in two blocks, same sign both times. The figures in that block are illustrative, as the badge says: what is real is the shape of the finding and what you do about it.

So the return is the herding knob. Turn the knob down and the edge goes with it, and real markets have no such knob, which is why this edge will not transfer. An agent whose return stayed flat across those six bins would have passed the strongest robustness test the simulator can give it.
