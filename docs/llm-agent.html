An LLM Agent

A worked example, not a library feature: examples/08-claude-agent.py defines a ClaudeTrader that implements the same agent protocol as anything else, and the harness scores it against the reference agents. Nothing in the library is Claude-aware, so any provider that returns structured output slots in the same way.

SHELL 
pip install "pretium[claude]"
export ANTHROPIC_API_KEY=...        # or: ant auth login
python examples/08-claude-agent.py

The interesting part is not that a language model can pick a portfolio. It is that this harness can check whether it picked one for the right reason.

The Second Score

Every agent gets a P&L. An agent that also implements explain(day) gets a second score on top: the harness compares the factor the agent blames for the day against the engine's own record of what actually moved prices.

OUTPUTMIXED, SEE NOTE
agent                     pnl    impact    why-right
oracle                 229751       ...         100%
claude                    ...       ...          ..%
momentum                21520       ...            -

The oracle and momentum rows are measured, by the same call the example makes: pt.reference_agents(seed=3) over Universe.random(12, seed=7), seed 2026, 20 days, max_leverage=2.0. The claude row is blank on purpose. Every run costs money, no published run exists yet, and one seed would not be worth quoting anyway. Run it and you get your own numbers.

The oracle scores 100% on why-right because it reads the true mispricing directly, which is also why it is a reference rather than a competitor.

A model can earn a good P&L by accident, and the second score is the one no real market can produce, because attributing a real price move to mean reversion rather than order flow is exactly the thing nobody can do. So the run gets at whether the model is describing the mechanism or telling a plausible story.

How It Is Wired

Claude returns a structured decision, so nothing has to be parsed out of free text.

PYTHON 
class Decision(BaseModel):
    weights: dict[str, float]   # -1.0 to 1.0 per ticker
    driver: Factor              # one of the engine's nine factors
    reasoning: str

response = self.client.messages.parse(
    model="claude-opus-5",
    max_tokens=4000,
    system=[{"type": "text", "text": SYSTEM,
             "cache_control": {"type": "ephemeral"}}],
    thinking={"type": "adaptive"},
    output_config={"effort": self.effort},
    messages=[{"role": "user", "content": self._prompt(obs)}],
    output_format=Decision,
)

driver is a literal of the nine components, so the answer comes from a closed set and can be checked against the truth table. messages.parse validates the response against the schema.

The market's rules go in the system prompt and never change, so they carry a cache breakpoint. The volatile part, prices and positions and the book, goes in the user turn after it. Put the market state in the system prompt and you invalidate the cache on every call.

The model returns weights rather than share counts, and the example converts them itself: divide by price, cap against average daily volume, difference against the current position. That is a few lines in the agent, and asking a model to do the arithmetic instead adds a place for it to go wrong. There is no library helper for it, because act is specified in shares (see The Agent Harness).

Known Traps

The harness steps six times a day. steps_per_day defaults to 6, so an agent that calls the API inside act without gating makes six calls a day and six times the bill. The example tracks the last day it acted on:

PYTHON 
if obs.day == self._last_day:
    return {}
self._last_day = obs.day

# equivalent, and preferred in new code:
# if not obs.is_first_step_of_day:
#     return {}

Those two are the same guard. obs.is_first_step_of_day is the one to reach for, because it cannot be confused with a once-a-run guard; the day-tracking version is what the example happens to use and works identically.

explain takes the day. The full contract is on The Agent Harness. The signature is explain(self, day), not explain(self). Getting it wrong raises nowhere you will notice: the harness records the error per day and reports explanation_accuracy as None, so the column reads - and looks like the feature is switched off.

Cost

One call per day, one day per decision. The default run is 20 days over 12 instruments, so 20 calls, which lands around $0.30 to $0.60 at Opus 5 rates with the system prompt cached. It scales linearly with days.

The mechanism does not need a frontier model to demonstrate. Pass model="claude-haiku-4-5" for a cheap smoke test and expect worse answers, particularly on driver.

What This Does Not Tell You

The same warning as everywhere else on this site, and it applies harder to a language model than to a coded strategy. This market has knowable structure, and the system prompt describes it. Under pt-v3 the residual trend in returns is small enough to sit inside the real-market band (+0.0375 against −0.08 to 0.06), but it comes from a herding coefficient that real markets do not have, and earlier presets ran it four times harder. A model that finds that dial and leans on it is exploiting the simulator rather than showing skill that transfers. If you run under an older preset, check what the prompt is telling it.

The why-right column is the more durable of the two scores, because naming the mechanism correctly is a claim about reasoning rather than about this market's quirks. Even then, run it across seeds before concluding anything, because on one market you are largely ranking the market.
