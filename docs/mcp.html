The MCP Server

pretium ships an MCP server, so a coding agent can drive the simulator through tool calls instead of Python. You ask in plain English: does a momentum strategy beat buy-and-hold here, and is the difference real?

Install and Register

SHELL 
pip install "pretium[mcp]"
claude mcp add pretium -- pretium-mcp

Or in a client's config file:

JSON 
{"mcpServers": {"pretium": {"command": "pretium-mcp"}}}

It takes no arguments and speaks MCP over stdio.

The Tools

Eleven, all read-only. Seven answer a question directly, two compose an input as data, and two run past what a conversation can wait for.

ToolWhat it answers
describe_simulator()What this is, what it reproduces, what it cannot do. Call it first.
check_envelope(horizon_days, statistics=[], sector_concentrated=false, scenario_magnitude=false)Is my question inside the certified range, before I spend anything on it?
validate_strategy(spec)Is this spec well-formed, and what is its fingerprint?
evaluate_strategies(strategies, seed, days, universe_size=…, universe_seed=…, preset=…)How do these do on one identical market?
rank_strategies(strategies, seeds, days, universe_size=…, universe_seed=…, preset=…)Which is really better, across seeds, with a paired sign test?
run_stress_scenario(kind, strategies, seed, days, …)What a rate, VIX or volatility shock does, always against its own unshocked control. kind is one of rate, vix or vol.
explain_price_move(seed, day, ticker, …)Why a price moved: the nine components that sum to it.
build_universe(size=40, seed=111, sectors=None, instruments=None, limit=20)Build a roster and preview it in one call, generated from size and seed with optional sector concentration, or from explicit instruments. Returns a universe document the run tools take, so a roster is composed once and reused rather than re-specified per call. A sector-concentrated roster is one of the five named envelope gaps, and this is what makes it askable.
build_scenario(steps, label="", ...)Compose a macro path as data from a list of steps, the same grammar the Python surface uses. Returns a scenario document the run tools accept.
start_job(tool, arguments={})Run one of the expensive tools in the background. This is how you reach the certified 252-day horizon, which a direct call cannot finish inside a conversation.
check_job(job_id=None)Poll a background run and collect its result. With no id, reports every job.

Sending a Strategy

You cannot send Python to the server. A tool call cannot carry a function, and accepting code as a string would turn this into a remote-code-execution endpoint with a market simulator bolted on. So the server speaks StrategySpec documents, the same declarative grammar that makes a result citable. The full grammar, every signal.kind and every default is in Tables and Schemas.

JSON 
{
  "signal": {"kind": "momentum", "lookback_days": 1.0},
  "portfolio": {"top_k": 5, "gross": 1.0}
}

One thing works differently here than in the library: if spec_version is missing, the server fills it in. Models writing a spec mid-conversation leave it out every time, and rejecting them for it wastes a round trip. If a spec does name a version, that version is kept, so anything newer than the build is still refused.

What the grammar cannot express: path dependence, conditional logic, custom signals. Those need a Python agent, and Running a Market is where that lives.

Every Result Carries Its Own Caveats

When you call pt.evaluate yourself, you have the docstrings and this site to hand. A model calling evaluate_strategies has the tool result and nothing else, and it will then summarise that result for someone with even less. Hand it {"return_pct": 88.7} and it will say the strategy made 88.7%.

So every result carries a caveats list beside its numbers. Two properties are worth knowing about.

Earned per Call

Each one fires on something about the call you actually made. A multi-seed run does not get the single-seed warning. A strategy with no momentum in it hears nothing about return autocorrelation. In practice, warnings that never change get skipped.

Computed at Call Time

Every number in them is read from the published realism figures when the tool runs, so a warning cannot go stale while the model it describes moves on.

WHY COMPUTED, AND NOT HARDCODED

While this server was being written, PRODUCT.md and README.md were both found still asserting a return autocorrelation of +0.219 and +0.249, from a superseded preset. The default has moved twice since that was written, from pt-v3 to pt-v10 at 0.2.0 and on to pt-v12 at 0.3.0, which certifies 0.0239: comfortably inside the real-market band of −0.08 to 0.06, and about a tenth of either quoted figure. This server never types that number. It reads it out of envelope.CERTIFIED on every call, so the sentence moves when the preset moves.

A hardcoded caveat is how a caveat becomes false, and a false caveat told to a model is worse than none.

SAMPLE OUTPUTILLUSTRATIVE
{
  "results": {"momentum": {"return_pct": 88.7, "sharpe": 1.94, ...}},
  "seed": 42,
  "days": 5,
  "caveats": [
    "SINGLE SEED: one market is one sample. This result measures the
     seed as much as the strategy. Use rank_strategies across seeds
     before stating which is better.",
    "SHORT WINDOW: 5 days. The statistics that make this market
     credible are 252-day measurements, so this run is a sample of
     the market rather than a description of it.",
    "This strategy trades a return-continuation or reversal signal,
     so its edge depends on the simulator's return autocorrelation:
     return_acf1 measures 0.0239 against a real-market band of
     -0.08 to 0.06 (in band) at the certified 252-day horizon.",
    "NOT A FORECAST: simulated performance does not predict live
     returns. Read this as a stress test."
  ]
}

If a summary drops the caveats, it is misreporting the result.

Seeds, and How Many

evaluate_strategies runs one market. It is fast and a fine first look, but a verdict from one seed is measuring the seed as much as the strategy.

rank_strategies is the honest version. It runs many seeds and reports paired_sign_tests, where both entrants traded the same market on each seed. Pairing them takes the market out of the comparison.

Quote pooled_capture, not seeds_first. The latter counts league positions among all entrants and splits arbitrarily on a tie. Try submitting a momentum spec against the momentum baseline: it comes back all ties, zero paired seeds. That is right, because they are the same strategy. A league table would have picked a winner on a coin flip.

Limits, and Why

LimitValue
max_days60
max_universe120
max_strategies8
max_seeds12

These are about wall-clock time and the library itself imposes none of them. Forty names with the baselines takes roughly 0.5s at 5 days, 20s at 60, and 95s at 252, and a tool call has to come back while someone is still waiting.

That last number is why max_days stops short of the tested 252-day horizon on a direct call, and why every scored result gets a SHORT WINDOW warning. The statistics that make this market believable were measured over a year, so a five-day run samples the market rather than describing it. When you need the full horizon, use start_job and check_job: the run happens in the background and the conversation collects it afterwards.

What the Server Leaves Out

  • Atlas. A survey is thousands of simulations and takes hours, so nothing useful could come back from it inside a conversation. Run it from Python.
  • The 87 model coefficients. You pick presets by name. Coefficients made up on the fly give you a market nobody calibrated, reported as though it were a shipped one.
  • Writes. Every tool is read-only and pure: same arguments, same bytes, every platform.
