Real Companies from EDGAR

Seed a universe from real SEC filings. The fundamentals are real; every price path stays synthetic.

When Real Fundamentals Help

A generated universe is plausible but far too tidy. Real filings are messy in useful ways: valuations spread properly, sector weights are lopsided, and loss-makers turn up in realistic numbers. If your strategy reads fundamentals, test it on this.

PYTHON 
snap = pt.edgar.fetch(as_of="2024-06-30", limit=100,
                      user_agent="Jane Roe jane@example.org")
snap.save("edgar-2024h1.json")     # the artifact: hashed, citable

universe = pt.Universe.from_edgar(snap, federal_funds_rate=0.03)
engine = pt.Engine(seed=42, universe=universe)

How It Works

  • The fetch uses EDGAR's XBRL frames API: five market-wide requests plus one per company kept. It takes a transport argument, so the whole derivation is testable without a network.
  • user_agent is required and must carry a contact address. The SEC's fair-access policy asks for one, and the library will not send a made-up one for you.
  • Each kept company becomes an Instrument with its filed fundamentals: eps, book value, shares outstanding, and the rest. The model then values and prices those fundamentals under the rate you pass, the same way it does for a generated roster.

Save and Cite the Snapshot

Companies amend their filings, so the same request will return different numbers next year. The snapshot file is what you cite: hashed, saveable, and enough to rebuild the exact same universe later. Cite the file, not the query.

WHAT THIS DOES NOT GIVE YOU

EDGAR carries no market capitalisation, so limit= ranks companies by shareholders' equity and the roster ends up skewed toward balance-sheet-heavy names rather than resembling a cap-weighted index.

And it loads fundamentals, not behaviour. A loaded ticker is a stock with that company's fundamentals under this model's assumptions. It is not that company: not its real volatility, not its microstructure, not its news flow.

From Filings to an Archived Result

The whole thing end to end. Fetch the filings, save the snapshot, look at what you got, measure realism on your own roster rather than borrowing the published numbers, run the strategy, then archive it so someone else can rebuild it.

PYTHON 
import collections
import pretium as pt
from pretium import envelope

# 1. fetch once, save the artifact, and cite THAT
snap = pt.edgar.fetch(as_of="2024-06-30", limit=60,
                      user_agent="Jane Roe jane@example.org")
snap.save("edgar-2024h1.json")       # hashed, citable, replayable

# 2. build the universe and look at what you actually got
universe = pt.Universe.from_edgar(snap, federal_funds_rate=0.03)
print(len(universe), universe.fingerprint)
print(collections.Counter(i.sector for i in universe))   # NOT balanced
print(sum(1 for i in universe if i.eps <= 0), "loss-makers")

# 3. this roster's own realism panel, with the seed spread beside it
panels = [pt.facts.measure(seed=s, universe=universe) for s in range(1, 7)]
print(envelope.report_intervals(envelope.intervals(panels)))

# 4. and the verdict for a concentrated roster
print(envelope.check(horizon_days=252, sector_concentrated=True,
                     statistics=["cross_sectional_corr"]))

# 5. now run the study on real fundamentals
spec = pt.StrategySpec.momentum(lookback_days=1.0, top_k=5)
scores = pt.evaluate({"mom": spec}, seed=42, universe=universe, days=252)
print(scores["mom"].return_pct, scores["mom"].pnl)

# 6. archive it: snapshot file + manifest is a rebuildable result
eng = pt.Engine(seed=42, universe=universe)
manifest = pt.RunManifest.of(eng, seed=42, universe=universe, strategy=spec)
open("run.json", "w").write(manifest.to_json())

Step 4 refuses, which is the right answer here. Use the panel from step 3 as the realism record for this roster. The published numbers describe a different roster. The sector counts in step 2 are usually why yours differ: 14 financials against a round-robin roster's 3 or 4 per sector changes what the market does. Step 4's two counts are out of the ten-statistic panel of the pt-v3 era and have not been re-measured since; what they establish is a property of the roster rather than of a preset.

Store the snapshot file and the universe fingerprint alongside your results. Re-running the same EDGAR query later gives different numbers, and a re-ordered roster gives a different market.
